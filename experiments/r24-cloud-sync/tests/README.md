# R24 作业跨设备浏览器复验

先准备 Node.js 22+、Python 3 和 Chromium，然后在本目录执行：

```sh
npm ci
TCL_TEST_SITE_DIR=/path/to/staged-site npm test
```

测试目录需要 stage-site.py 生成的静态候选。未设置 TCL_TEST_SITE_DIR 时读取上一级 site/。

默认 Chromium 位于 `/usr/bin/chromium`。其他安装位置可设置
`CHROMIUM_EXECUTABLE`。测试服务器仅绑定 127.0.0.1，通过 HTTP 调用真实
`backend/api.mjs` 及内存存储，并使用仅本机可访问的合成姓名、一次性绑定码及设备令牌映射。它不会写入
或访问腾讯云。测试使用测试代码生成的三题 XLSX，媒体流程走应用的文字模式。

复验内容：

- 两个隔离浏览器上下文。运营上传 XLSX、预览并发布，主播按运营姓名搜索、
  领取、按冻结题目顺序输入三题答案并提交，运营在另一个上下文直接读取每题回答。
  主播重载页面后仅输入姓名即可查看同一作业的云端提交状态。
- 注入服务器写入成功后的首次响应中断。页面须显示未收到确认，重试须取得同一条
  提交记录，运营只能收到一条。
- 首次仅输入姓名必须进入绑定环节。绑定码错误、属于其他用户或已经使用均无法进运营端。
  同一浏览器退出后仅凭姓名和此前保留的设备令牌重新验证。
- 另一团队主播刷新后无法发现本团队作业。主播界面没有运营发布入口。
- 未配置后端的版本仍可用 JSON 作业包和回执交接，页面将本机保存与云端送达区分。

本测试采用 Chromium 自动化和模拟身份目录。无法替代云端部署、CloudBase 实际设备认证、
真机、媒体采集和公网连通性验收。
