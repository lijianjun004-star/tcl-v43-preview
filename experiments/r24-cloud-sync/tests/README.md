# R24 作业跨设备浏览器复验

准备 Node.js 22+、Python 3 和 Chromium。在当前目录安装依赖后，指定由 `stage-site.py` 生成的静态候选。

```sh
npm ci
TCL_TEST_SITE_DIR=/path/to/staged-site npm test
TCL_V2_LOCAL=1 TCL_TEST_SITE_DIR=/path/to/staged-site node v2-smoke.mjs
```

默认 Chromium 路径为 `/usr/bin/chromium`，可用 `CHROMIUM_EXECUTABLE` 覆盖。本机模式连接 127.0.0.1，使用真实的业务 API 处理器和内存数据，写入在测试结束后消失。

常规回归用例覆盖跨浏览器发布、领取、提交，服务端已经写入但首个响应丢失后的重试去重，已登记姓名与设备的登录兼容，设备码生成确认及失败反馈、角色隔离与本机体验。刷新回归在配置与作业响应延迟期间检查云同步加载提示、已绑定状态、未提交复盘恢复、导航后作业计数更新及原回答。V2 流程用例新增以下检查。

一键出题用本地替身模拟 CloudBase 文本模型。只有已开放的运营会看到按钮，文字和表格可生成可编辑草稿。测试分别核对生成时的模型请求、人工确认后发布的作业以及主播看到的弹幕。真实模型的权限、额度和响应需在已授权的试点环境单独验证。

- 两名合成测试人员分别自动开通。运营发布合成 XLSX，主播搜索领取并提交三题文字及 Chromium 合成录音。
- 运营刷新后看见该次提交和逐题文字，并验证至少一段云端音频可播放。
- 检查生成器显示、剪贴板和下载文件的 28 字符设备码逐字节一致。
- 独立浏览器选错角色时按原角色显示；已更换的旧码失效；全角与空白粘贴规范化后绑定成功并读取原提交；第三个浏览器重复使用得到 `CODE_USED`。
- 绑定浏览器刷新后验证设备凭证并直接进入。
- 本机模式可加 `TCL_V2_DELAY_ASR=1` 模拟首次加载模型较慢，确认核对后的人工答案和逐题录音仍可提交。

`node v2-smoke.mjs` 的默认目标是上海公网试点，实际写入两条合成账号、一份作业、一次领取、一次提交及最多三段录音。仅在已授权的发布验收中采用此模式。脚本将目标限定在试点网址及 API，输出脱敏步骤和 HTTP 状态计数。复验旧版时用 `TCL_V2_EXPECTED_VERSION` 指定页面短版本。需要代理时用 `TCL_PILOT_PROXY` 指定。实体手机、微信和真人口播均需单独验证。
