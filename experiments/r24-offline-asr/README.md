# R24 离线录音转写

收到合格的新增录音后，GitHub Actions 将音频以中文提交到 OpenAI 的文件转写 API，供人工核对。任务只传声音、语言和模型设置。结果保存在运行页面的 `r24-asr-review-运行编号` 下载包，保留 3 天。原始录音不放进下载包。每份文本对应一个请求号和用量记录。缺少的服务端字段以 null 表示。

## 公开验收

本仓库只允许指定分支上的一段固定合成 WAV 触发该任务。提交时校验文件的 SHA-256。参照文字用于事后比对。请勿将主播录音放进公开 Git 仓库、Issue 或工作流输入框。

## 私有仓库内的授权批次

适用于获准在 Git 历史中保存并交给 OpenAI 处理的录音。录音会保存在 Git 历史中，三天的下载包保留期只适用于转写结果。使用方和数据应符合所用服务的地区及数据处理要求。

1. 将本目录与 `.github/workflows/r24-offline-audio.yml` 放入获准使用的私有仓库。设置 Actions Secret `OPENAI_API_KEY` 和仓库变量 `R24_OFFLINE_ASR_ENABLED=true`。
2. 往已有的 `main` 分支正常提交 `asr-review-inbox/编号.wav` 等新录音。编号可用 1–40 个英文字母、数字、下划线或短横线。一次最多 3 段，每段不超过 512 KiB。支持 WAV、MP3、MP4、M4A、MPEG、MPGA、WebM、FLAC、OGG。请在提交前完成授权和大小检查。
3. 在 Actions 的 **R24 offline audio transcription** 下载结果，打开 `transcripts/编号.txt` 核对原话。Git 中已经处理或出现过的同一音频内容、同名文件编辑、重复运行和强制推送均跳过。全新的授权录音使用新的编号。API 失败时保留请求记录，已发起的请求不自动重试。

## 练播房现有入口

上海练播房的本机转写、主播校对和提交路径独立运行。本功能处理离线资料。要在主播页面提供自动转写，仍需受限私有音频存储、后台任务编号和结果回填，并确认该业务可以使用所选模型服务。页面应让主播回听、更正并确认后提交。
