# 导入数据链路有界审查与修复

执行范围：实际 Chromium 运行产品解析器和导入界面；CSV/JSON 为构造文件，DOCX 由 python-docx 生成，XLSX 同时包含构造容器与 openpyxl 生成器兼容回归。没有读取用户手机本机数据库，没有调用 Gemini，不把合成输入的缺陷当作真实业务库已被污染的证据。

## 确认并修复的数据问题

| 输入触发 | 修复前实际结果 | 当前行为 |
| --- | --- | --- |
| 模板包含 HDR10 和 HDR10+ 两道题 | 去重删除 `+`，两题合并，第二答案附在第一题 | 保留型号/版本符号，仅统一全半角、大小写、空白和句末问号等；两题独立 |
| DOCX 表头水平跨两列，正文保留独立备注列 | 忽略 gridSpan，备注被映射成答案，真正答案漏掉 | 展开空占位保留网格列坐标；答案列正确 |
| XLSX 工作簿顺序不同于 sheet1/sheet2 文件数字顺序 | 冰箱回答的来源标成电视，反之亦然 | 使用 workbook.xml.rels 关联名称与实际路径，支持非数字文件名；缺失或外部关系明确拒绝 |
| JSON 回答为 0/false，或问答为嵌套对象 | 0/false 被吞为空，嵌套对象写成 `[object Object]` 且待审核 | 保留字符串/数字/布尔标量，嵌套问答/非法要点明确报错，不猜测对象结构 |
| 回答超过3000字，问题超过500字、要点超过12条等 | slice 无提示删除后文，可能丢末尾约束 | 沿用容量限制，超过即说明来源和字段并要求拆分，不截断入库 |

`import-mappings-before.json` 与 `import-limits-types-before.json` 保留修复前实测失败。`import-mappings-after.json` 是本轮 24 个针对性用例及既有题库型号区分检查，记录两份产品模块测试前后 SHA，结果 PASS。`regression/` 保存重新执行的正常/异常导入、两种完整 Office 生成器兼容结果，没有覆盖早期交付证据。

额外已向总负责人报告：501条有效CSV解析得到501条，但旧界面仅显示并保存500条，无截断说明，缺最后一条。证据在 `import-limits-types-before.json`。此项由 app.js 所有者单独修复为超限整批拒绝；本文不代替其最终界面实测。

## 当前输入约定及未覆盖范围

建议使用模板标准表头 `问题/优秀回答` 或 `弹幕内容/案例话术1/案例话术2`；编号用半角数字，普通问题写完整句子。当前全角“案例话术１”不识别为答案列；普通问答格式中两字短问（例如“安装”）可能跳过；无表头且首行含“问题”可能被误识别为表头。这三种非标准输入已在前报告复现，本轮按范围约定没有扩展猜列规则，不能宣称任意格式均无损导入。

UTF-8 BOM、表头周围空格、带引号的跨行CSV回答已验证正确。非UTF-8输入会拒绝并要求另存为UTF-8，现有错误提示仍沿用“TXT/JSON”措辞。尚未验证实际244条私有讲解词、所有Office版本/纵向合并/嵌套表格、所有字符编码或真实云端导入接口。
