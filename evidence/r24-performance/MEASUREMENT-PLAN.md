# 卡顿与页面稳定性测量计划（实现前冻结）

基线产品取自 git 3672708，独立完整静态副本 `/workspace/scratch/r24-perf-baseline`，app SHA256 d090543e3bdd010dfa95580c4f6a5dcd7185f116225ff02674120954c10cbecf。所有场景为人工构造，不含业务原表、用户音视频或模型调用。

使用相同桌面 Chromium、390×844 触摸视口，记录浏览器版本；CDP CPU 1×和4×分别对20、100、200题复盘各做3个独立浏览器上下文样本。每个样本在原生 IndexedDB 装入500条人工资料和对应题数的人工历史快照，然后完全使用现有恢复、复盘和输入UI。模型不加载，媒体为空。

采样：恢复总览耗时和总DOM节点数、总览是否提前创建隐藏逐题行、打开逐题耗时及行数、录后文字中40个输入事件产生的读写事务/records.put次数、输入到下一帧时延分布、Long Task次数/最长值/总阻塞时间、保存结束延迟；刷新同姓名恢复后必须保留完整末尾40字。DOM/IDB/LongTask只读计数器不改变应用分支。

额外检查：500条资料搜索保持结果正确、30次普通页面切换后interval数不增长；已访问可见表单控件计算字号不低于16px；整页宽度不超过viewport（表格/局部容器允许内部滚动），visualViewport.scale保持1。这些不是iOS实机自动缩放验证，真机键盘及手势需另验。

验收优先采用可复现结构目标而不是微小耗时差：复盘总览不预建整张逐题表；初始逐题页最多20题并可访问全部题目；连续40字输入不应产生40次完整会话提交，目标每样本不超过8次且末尾数据不丢；切页不残留计时器、无页面错误。报告逐样本原始耗时、中位数和范围，不把桌面4×节流或小样本比例表述为真实手机整体提升。
