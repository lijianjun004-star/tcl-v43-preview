# R25 跨设备后台接通验收方案

任务：TCL-R25-CROSS-DEVICE-ACCEPTANCE-20261116。总负责人：ChatGPT/root；当前分工：Codex 只读验收准备。状态：**PLAN / 全部待执行**。本分工没有修改源码、创建云资源、部署、调用付费 API 或执行账号操作。

## 验收对象与边界

目标闭环：主播完成练播并提交 → 指定运营在自己的独立会话收件 → 运营保存反馈 → 原主播在自己的会话读取反馈。记录与授权由真实服务器及持久存储决定。

当前 R25 源码的姓名/角色选择、IndexedDB 提交和 BroadcastChannel 只用于本机体验；姓名不是安全认证。现有 `remote()` helper 或“已提交给运营”文字不能证明后台接通。新验收必须覆盖实际接入的身份、API、数据库与媒体存储，不能用同一浏览器切换姓名替代跨设备证明。

| 层级 | 执行条件 | 可以证明 | 不能据此声称 |
| --- | --- | --- | --- |
| L：本地真实后台 | 实际运行后端进程与持久数据库/私有媒体目录；浏览器真实请求该 API | API、权限、提交/反馈及本地重启持久化 | 公网可达、托管平台配置、真手机 |
| P：公网真实两端 | 实际 GitHub Pages R25 前端 + 已部署公开可达 API + 正式配置的持久数据库/私有媒体存储；两独立浏览器上下文 | 公网前后端、真实认证与两个隔离存储上下文的读写闭环 | 两台物理手机、iPhone 录制兼容性、国内网络或 ASR 准确率 |

本地与公网分别出结果。L 通过不能填成 P 通过。正向闭环不允许 mock/fulfill API 响应或绕过身份校验；只在指定负面用例注入断网、丢响应等故障，并单列该范围。

## 固定测试数据与环境

- 至少创建两个互不共享 `storage_state` 的浏览器上下文：主播 A、运营 O。cookies、localStorage、IndexedDB、CacheStorage 全部隔离；每端先记录存储为空。不向另一端复制 IndexedDB、localStorage、token 或恢复包。
- 负面权限用例另用主播 B、未获此提交授权的运营 O2、匿名上下文；如使用不同团队/空间，按最终平台的归属规则配置。显示名称可重复，服务器身份 ID 必须不同。
- 使用唯一运行标记 `r25-cross-device-<UTC时间>`。主播练播两题，问题、参考答案、型号/SKU、来源、人工修改/人工清空标记、题目 ID、场次 ID 都有明确预期；不使用真人姓名或真实商业资料。
- 媒体只用小型合成音频/视频或测试图，预先记录字节数、MIME 和 SHA-256；不上传员工录音。纯文字闭环不得为了验收额外加载 ASR 模型或接模型 API。
- 测试前固定并记录：前端提交和实际 `app.js` 响应 SHA、后端提交/部署版本、API origin、数据库迁移版本、认证方式、运行时间、测试账号的脱敏 ID。API 路径在平台确定后绑定到具体契约，以下用业务操作命名，避免先假定供应商实现。
- 设置可配置的等待上限（初始 30 秒，仅为测试预算），记录实际收件/反馈可见耗时。若依靠刷新或轮询，明确记录；不宣称实时推送。

## 必须执行的验收用例

| 编号 | 操作与故障注入 | 必须观察到的结果与证据 |
| --- | --- | --- |
| I1 身份可信 | A 与 O 分别使用实际支持的认证入口登录，读取“当前身份”；A 修改本地姓名、角色、请求体 `owner/role/operatorId` 后再次请求受保护资源 | 服务器按认证主体决定身份与权限；本地角色切换和客户端传入身份字段不能提权。保存脱敏当前身份响应和拒绝请求的状态码 |
| I2 错人不见 | A、B、O、O2、匿名分别尝试列表、详情、修改、反馈和媒体授权操作；已知有效 submission/session/media ID 直接请求，避免只测空列表 | A/O 仅拥有业务关系允许的权限；B/O2/匿名被服务器拒绝或返回不暴露资源的 404。不能先返回所有记录再由前端按姓名过滤 |
| C1 两端提交收件 | A 完成两题并提交给 O；保留真实 API 请求/服务端返回的 submission ID；O 在自己的上下文刷新/轮询收件箱并打开详情 | O 获得同一服务端 ID 与完整两题快照，题序、原问题、答案、型号/SKU、来源及手改/清空标记匹配。O 的本地存储初始为空，且未导入 A 的数据；数据库/API 回读与 UI 一致 |
| C2 反馈返回主播 | O 为该 submission 保存一条唯一标记的人工反馈；A 刷新或主动读取反馈 | A 读取同一 submission 下、由 O 创建的已持久化反馈；B/O2 不得替他人写反馈或读取无权反馈。记录反馈 ID、服务端作者 ID、正文与两端截图 |
| C3 失败不冒充送达 | 提交前断网、API 返回 5xx/非 JSON、认证过期、数据库写入失败分别执行一次；只在测试实例可控注入数据库失败 | A 保留本机草稿，明确显示未确认提交/可重试；不得出现“已送达”或已提交标记。O 无新增成功收件。不能仅凭 HTTP 请求已发出或本地 IndexedDB 成功更新判为送达 |
| C4 成功后响应丢失 | 让真实服务器完成提交并持久化，再仅丢弃其 HTTP 响应；A 看到未确认后按原提交操作重试 | 服务器以稳定的幂等键/场次唯一约束返回同一 submission ID；O 仅有一条记录。保留“首次服务端已提交、客户端未收到响应”的证据，不能以请求未到服务器的普通断网代替 |
| C5 并发和重复操作 | A 双击提交、两个并发请求使用同一幂等键、页面刷新后再次提交；同一键换不同内容；同一反馈重复发送 | 正常重放不新增重复记录或重复媒体；同键不同内容被明确拒绝或要求新的操作版本，不能静默混合。UI 防双击不能代替服务端唯一性。反馈重放也不能重复出现 |
| D1 浏览器刷新 | A 提交成功后刷新；O 收件/反馈后刷新，两端分别退出再重新登录；另建全新 O 上下文重新登录 | 已成功提交的记录与反馈从服务端重新读回，ID/内容不变；不能依靠上个页面内存或已有 IndexedDB 内容才显示。检查当前响应真实来自 API |
| D2 后端重启 | 在本地真实后端创建记录、反馈、媒体；关闭并重启进程，使用同一持久存储。公网若支持安全的测试实例重启/部署新 revision，也独立执行 | 新进程及新浏览器上下文仍能读到完全相同的记录、反馈、媒体和权限关系；数据库路径/存储卷不在进程临时目录。若托管平台无法主动重启，P-D2 标 NOT RUN，不能用刷新页面或 health=200 替代 |
| D3 空白端取证 | 提交后关闭全部浏览器，再用两个新上下文登录 A/O 读取记录与反馈 | 闭环仍成立。证明服务端是共同来源；不能用同机 BroadcastChannel、共享 service worker 或复制存储让测试通过 |

## 媒体私有授权验收

以下用例对声明支持云端音视频的版本是必须项。若本轮仅开放文字同步，应在产品和报告明确写“媒体仍仅本机、尚未接通”，不得把文字闭环通过表述为音视频跨设备通过。

| 编号 | 操作 | 必须结果 |
| --- | --- | --- |
| M1 私有上传与回读 | A 上传一份带 SHA-256 的合成媒体并绑定自己的提交；O 通过该提交申请回放 | 元数据、上传完成状态、存储对象与 submission 绑定正确；O 下载字节 SHA 与 A 上传完全一致。存储对象不在公共 bucket/静态站点；普通无授权 URL GET 不能读取 |
| M2 对象级权限 | B/O2/匿名用已知 media ID 请求详情、下载授权、删除/替换；A 尝试把媒体绑定到别人的 submission | 服务端逐对象拒绝，不能凭路径难猜或前端按钮隐藏充当授权。请求体 owner/recipient 与文件名不可改变权限归属 |
| M3 短期凭证 | 若使用签名 URL，O 经认证申请，随后测试过期、篡改签名、无授权主体申请 URL；若使用认证代理下载，分别测试有效/过期会话 | 只有获授权主体能申请，URL 过期/篡改不可读；记录 TTL 和结果，不把 bearer 签名 URL 错写为与账号强绑定。若短期 URL 在有效期内被转发可读，这是实际凭证语义，报告须如实写明；需要账号绑定隐私时应使用鉴权代理 |
| M4 中断和失败 | 上传截断、取消、超大小、声明校验和不符、对象存储失败；随后重试原操作 | 不把未完成对象展示为可回放成功；失败状态可见，文字提交的状态符合明确定义的部分失败策略。重试不重复挂载，不泄露孤立对象。无需真人媒体 |
| M5 隔离恢复 | 关闭浏览器/重启受测后端后，A/O 重新登录回放；B/O2 再试 | 合成媒体字节与权限关系保持；客户端不能因为丢失 object URL、内存 Blob 或本机缓存而无法云端回放 |

签名 URL、cookie、Authorization、账号登录链接或服务端密钥不得写入公开证据。证据只记录脱敏 URL/操作类型/主体/状态码、对象 SHA 与过期结果。

## 证据产物与判定

每层各保存 `L/`、`P/`，避免混用来源：

- `environment.json`：精确前后端版本、部署/API origin、数据库版本、账号脱敏映射与浏览器隔离方式。
- `execution.json`：逐用例命令/步骤、开始结束时间、真实请求 ID、脱敏状态码、服务端资源 ID、预期/实际值、PASS/FAIL/NOT RUN；故障注入另标，失败原件保留。
- 两端截图或短录屏：提交状态、O 收件/反馈、A 回读、错误状态；人工核对截图内容与返回数据一致。截图不含认证凭据。
- 原始客户端日志与允许取得的服务端日志/数据库回读（均脱敏）；媒体仅保存测试对象的大小/MIME/SHA，不发布真实员工内容。
- `SUMMARY.md`：分别列 L/P 的通过项、失败项、未运行项；注明模拟移动布局与物理设备区别，注明媒体实际支持范围。

放行条件：已声明范围内的 P0 正向闭环、对象级权限、失败不冒充送达、幂等重试、刷新持久化全部通过。L 重启持久化须通过；P 无法安全重启时保留该限制。任何提权、越权读取、重复收件或未确认却显示成功均为阻断项。单个端点返回 200、两份截图、两个模型同意、仅本地缓存或单个浏览器切换身份都不构成跨设备验收。
